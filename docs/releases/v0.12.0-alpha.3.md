# goSignals v0.12.0-alpha.3

Released: TBD
Compare: [v0.12.0-alpha.2...v0.12.0-alpha.3](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.2...v0.12.0-alpha.3)

## Why this release

alpha.3 brings goSignals into compliance with the **OpenID SSF 1.0 final**
specification. Earlier versions tracked a much older SSF draft; this release
runs the full OpenID conformance suite end-to-end against both the transmitter
and receiver halves and lands the spec deltas the suite surfaced. It also adds
the conformance harness itself to the repo so any contributor (or downstream
operator) can rerun the matrix locally.

No data-layer migrations. The wire-level changes are spec corrections, so a
strict SSF 1.0 client that previously interoperated by accident will now
interoperate by spec. A client that was relying on the off-spec behavior
(HTTP 200 on stream delete, an empty transmitter-supplied `aud`, the
non-standard receiver-side `/status` health probe, etc.) will see the new
behavior described below.

## Conformance harness (new)

A self-contained deployment + runbook for running the OpenID conformance
suite's SSF test plans against goSignals — all artifacts live under
`conformance/`:

- `docker-compose-conformance.yml` — goSignals + single-node Mongo replica
  set, published on host `:9443`, with the cert mount and host-gateway
  push-callback wiring the suite needs.
- `docker-compose-conformance.build.yml` + `Dockerfile.conformance` — an
  override that compiles goSignals from the working tree (and bakes in the
  `goSignals` CLI) so local fixes can be rebuilt and retested in a loop.
- `bootstrap-token.sh` — mints the suite's stream + event access token and
  templates the transmitter suite config.
- `run-plan.sh` / `run-receiver-plan.sh` / `run-all-plans.sh` — per-plan and
  full 4-transmitter + 4-receiver matrix drivers with an aggregate Markdown
  summary; `PLANS_FILTER` selects a subset.
- `trigger-caep.sh` — helper that fires operator-driven CAEP events into the
  server via the new out-of-band trigger.
- `README.md` — full runbook and environment-variable reference.

Generated artifacts under `conformance/results/` and the derived
`suite-configs/*.local.json` (which carries a live minted token) are
gitignored.

## Wire-level / spec fixes

### Transmitter

- **Stream delete now returns `204 No Content`** (was `200 OK`). SSF 1.0
  §8.1.5 requires 204.
- **PUT / PATCH `/stream` resolves the target from the request body's
  `stream_id`** when no `stream_id` query parameter is supplied (SSF
  §8.1.1.3). The body's `stream_id` is now the authoritative target; the
  query parameter remains supported and is preferred when present.
  Receivers that send only the body (the conformance suite, and many real
  clients) no longer get a 404.
- **`aud` is always populated by the transmitter** on stream create
  (SSF §7.1.1). When the request omits it, goSignals fills in the most
  specific stable receiver identity available: the registered `client_id`
  for a locally issued token, falling back to the project id. Previously
  an unspecified `aud` was left empty, breaking audience validation at
  the receiver.
- **Subject-control endpoints are advertised when subject filtering is
  enabled.** `add_subject_endpoint` / `remove_subject_endpoint` now appear
  in the SSF configuration document whenever
  `I2SIG_SUBJECT_FILTERING=ENABLED`. The routes and handlers were always
  present; only the discovery advertisement was gated.
- **Enabling subject filtering no longer black-holes events.** With subject
  filtering on server-wide, a create request that omitted `default_subjects`
  previously left the baseline empty and silently dropped every
  non-operational event. The create path now seeds an empty baseline to
  ALL (per SSF §8.1.3, where add/remove-subject is an optional narrowing
  of an existing subscription). Pass-through relay streams are excluded —
  they perform no local filtering.

### Push delivery (RFC 8935)

- **`tx_tls_skip_verify` is now wired end-to-end.** The
  `tx_tls_skip_verify` stream-configuration field has been dead since
  introduction; the create path now copies it and applies an
  `I2SIG_TX_TLS_SKIP_VERIFY` deployment-wide default. Push delivery honors
  it so the transmitter can reach receivers presenting self-signed or
  SAN-less certificates (dev stacks, the conformance suite).
- **Receiver-side `/status` health probe is now optional.** SSF §7.1.3 /
  RFC 8935 place the stream-status endpoint on the **transmitter** — a
  standard push receiver exposes none. Earlier goSignals versions still
  GET-ed `<push-endpoint>/status` on the receiver, both as a pre-flight
  check before the first delivery and from the recovery loop after a
  failure. The new `I2SIG_PUSH_DISABLE_RECEIVER_STATUS` knob skips both
  calls. Push delivery proceeds without them; a receiver pause is still
  observed via the push response. Required to run the conformance push
  plans.

### Receiver

- **Stream delete cascades to the transmitter** (SSF 1.0 §8.1.1.5). When a
  receiver deletes a stream it auto-registered against a transmitter, it
  now resolves the transmitter's `configuration_endpoint` and issues
  `DELETE …?stream_id=<remote_stream_id>`. Best-effort — failures are
  logged and never block local deletion; 200, 204, and 404 are all
  accepted.
- **In-flight long-poll is drained before the delete cascade.** Deleting a
  polling receiver previously cancelled the open long-poll mid-request,
  which then raced the cascade DELETE against transmitters that serialize
  per-stream calls. The receiver now signals the poll loop to wind down
  between polls, bounded by the long-poll timeout plus slack, and only
  falls back to the prior force-cancel on timeout.
- **Receiver-initiated stream verification works on POLL** (SSF §8.1.4.2).
  Previously only PUSH streams could initiate verification. POLL streams
  now resolve the transmitter's `verification_endpoint` and post a
  verification request once per stream; the resulting SET arrives on a
  subsequent poll. The verification request now also carries the required
  `stream_id` on both push and poll paths.
- **Transmitter status / verify endpoint resolution uses
  insertion-style well-known discovery** (RFC 8615 — the well-known
  suffix is inserted between the issuer's host and path, not appended).
  Previously the bare issuer URL was fetched directly, which never
  matched the transmitter's published discovery document.
- **Status calls address the transmitter by the transmitter's stream
  id**, not the local one — prior code asked the transmitter about a
  stream it had never heard of.
- **Registration token is retained when the transmitter omits the poll
  `authorization_header`.** RFC 8936 permits the header to be absent;
  the receiver previously blanked its token and lost access to every
  subsequent call. The push path's existing fallback now applies to
  poll.
- **Per-stream transmitter TLS settings are honored on every outbound
  call** — discovery, registration, status, JWKS fetch, poll, delete. A
  transmitter with a self-signed cert previously failed verification on
  JWKS load and retried indefinitely, flooding the peer.
- **`stream_id` is omitted from the stream-registration request.**
  `stream_id` is a transmitter-assigned read-only property; the empty
  value the receiver was sending caused strict transmitters to reject
  the create.
- **String-valued `aud` is tolerated in transmitter responses.** RFC
  7519 §4.1.3 permits either a single string or an array; a scalar
  value is now coerced into a one-element array on decode.
- **`aud` and `iss` from the transmitter's response are now adopted by
  the receiver** on both POLL and PUSH branches, overriding what was
  requested (per SSF §7.1.1 these are transmitter-asserted).
- **Receiver-side `POST /status` carries `stream_id` in the body and
  `Content-Type: application/json`** (SSF §8.1.2.2). Without these the
  status update was silently rejected and the stream-status-update flow
  timed out (~240 s).

### Receiver management exercise (opt-in)

A production receiver does not spontaneously mutate its own stream, but the
SSF receiver conformance plan expects to observe a receiver-initiated
read / update / replace / status-update round before it can verdict the
stream. The new `I2SIG_RCV_MANAGEMENT_EXERCISE` flag (off by default) makes
a poll receiver perform one best-effort GET / PATCH / PUT / POST `status`
sequence against the transmitter before it opens its first long-poll —
sequential, so it never races a concurrent poll on a single-threaded
transmitter. Enabled in the conformance environment; harmless to leave off
in production.

## Discovery and local issuers (ADR 0023)

- **Path-bearing issuers hosted on this server are now first-class.** An
  issuer rooted at the server's own base URL ("local" — distinct from a
  "foreign" issuer the server only relays) is addressed by its full path,
  so SSF §7.2.4's binding among the issuer URL, the `iss` claim in signed
  SETs, and the `jwks_uri` holds even when the issuer carries a path.
  Discovery and JWKS routes accept a multi-segment path; the discovery
  handler reconstructs the full issuer URL, returns 404 if no signing
  keys exist for it, and advertises a clean
  `jwks_uri = <server-base>/jwks/<issuer-path>`. Relayed (foreign)
  issuers continue to reference the original publishing entity. See
  [ADR 0023](../adr/0023-local-issuer-addressing.md).
- **Discovery URLs now use RFC 8615 path-insertion** in both the CLI's
  `add server` probe and the receiver-plan driver. The well-known suffix
  is inserted between host and path
  (`host/.well-known/ssf-configuration/test/a/<alias>`) rather than
  appended. A host-only issuer URL is unchanged.
- **URL-shaped issuer ids are percent-encoded** in `POST /key/{keyName}`,
  so a key uploaded under an issuer like `https://host/issuer1` lands at
  the correct route. A slash-free issuer id behaves the same as before.

## CLI

- **New top-level commands:** `patch` and `replace` for stream mutation
  (PATCH and PUT). PATCH builds the request body from explicitly set
  flags only; PUT seeds the body from the cached configuration. Unset
  `events_requested` no longer marshals as JSON `null` (some strict
  receivers reject it).
- **CREATE request bodies strip transmitter-supplied fields**
  (`stream_id`, `iss`, `aud`, `events_supported`, `events_delivered`,
  timeouts) per SSF §7.1.1. Strict transmitters reject bodies that
  include them.
- **CREATE response decoding normalizes a scalar `aud` to a one-element
  array** so peer transmitters that return either form (RFC 7519 §4.1.3)
  decode cleanly.
- **`add server` preserves the host URL's path prefix** so discovery
  resolves under `/<path>/.well-known/ssf-configuration` rather than the
  server's root metadata.
- **`set stream status` sends `stream_id` in the body** with
  `Content-Type: application/json` (see SSF §8.1.2.2 above).
- **One-shot mode (`-c`)** now exits on parse error instead of dropping
  into the interactive shell.
- **`GOSIGNALS_HOME`** auto-creates its parent directory when missing
  (matching the default-path behavior).

## Out-of-band event trigger

`POST /trigger-event` is now implemented, so an operator (or the
CAEP-interop conformance module) can fire a SET directly into the server
without going through the normal inbound delivery path. It accepts the
admin / root tokens and the bootstrap bearer used for key administration,
and threads request-supplied `event_data` into the SET payload as a JSON
object (per RFC 8417 §2.2). Triggered events are routed only to streams
explicitly addressed by the request, not broadcast to every matching
stream — so a long-running test environment with leftover streams from
prior runs no longer sees duplicate, unauthenticated deliveries.

## New environment knobs

| Variable | Default | Purpose |
|---|---|---|
| `I2SIG_TX_TLS_SKIP_VERIFY` | off | Deployment-wide default for `tx_tls_skip_verify` on push streams. Useful for dev stacks and conformance runs where the receiver presents a self-signed or hostname-mismatched certificate. |
| `I2SIG_PUSH_DISABLE_RECEIVER_STATUS` | off | Skip the non-spec receiver-side `/status` probe on push streams (both the pre-flight before the first delivery and the per-stream recovery loop). Enable when delivering to a standard SSF receiver that does not expose `/status`. |
| `I2SIG_RCV_MANAGEMENT_EXERCISE` | off | Have a poll receiver perform one read / update / replace / status-update round against the transmitter when its stream comes up. Intended for conformance evidence; leave off in production. |

`I2SIG_SUBJECT_FILTERING=ENABLED` is unchanged in default, but now actually
controls advertisement of the subject-control endpoints in the SSF
configuration.

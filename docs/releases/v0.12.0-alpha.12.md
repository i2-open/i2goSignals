# goSignals v0.12.0-alpha.12

Released: TBD
Compare: [v0.12.0-alpha.11...v0.12.0-alpha.12](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.11...v0.12.0-alpha.12)

## Why this release

alpha.12 is a small **enablement round**: it hands the enterprise retention
drive-loop the one handle alpha.11 left unreachable, finishes the family
canon-migration on this repo, and takes the community share of two
family-lockstep chores (the Keycloak 26.6.4 substrate bump and a Go dependency
refresh). Nothing here touches the SSF wire — SET issuance, streams, and
transports behave exactly as at alpha.11.

The headline is the **live `EventDAO` export** (#229, PR #230). alpha.11
shipped the retention engine, the `OccupancySink` seam, and the DAO retention
primitives, but `dbProviders.OpenPersistence(...)` exported the services +
`Storage` + `Coordinator` and **not the `EventDAO`** — so an enterprise
embedder could not construct `services.NewRetentionEngine(...)` bound to the
running store. `Persistence` now carries the live, storage-backed `EventDAO` —
the same instance the running router's `EventService` writes through — which
unblocks the enterprise per-stream leader's retention purge + daily occupancy
sampling (enterprise ADR 0055 A5.2; enterprise #111 / #114). The change is
additive and off the wire; enterprise re-pins its community require past this
commit (`20ec982`) to light it up.

The rest is hygiene with one Go-API caveat for embedders. The repo gains the
family's `make seams` cross-repo self-check (PR #231) with `go vet` promoted
to a **hard gate**, and clearing the repo's pre-existing vet debt renamed the
anonymous embeds in two generated wrapper models — code that relied on field
promotion through `OneOfSimpleSubject` / `ScimResource` must now name the
inner struct. Neither wrapper sits on the SET wire path, so protocol payloads
are unchanged.

## Live EventDAO for the retention drive-loop

- **#229 — expose the live `EventDAO` on `dbProviders.Persistence`**
  (PR #230, merge `20ec982`; impl `752f610`, docs `c2a4ec4`). New
  `GetEventDAO() interfaces.EventDAO` on the provider `serviceSource`
  interface and a new exported `EventDAO` field on `Persistence`, populated in
  both `persistenceFromMemory` / `persistenceFromMongo` and in `Refresh()`.
- **Same-instance guarantee.** The memory provider returns its
  `notifyingEventDAO` wrapper (reassigned on `ResetDb(true)` rebuild so it
  stays in lockstep with the rebuilt `EventService`); the Mongo provider
  returns the stable, in-place-rebound `EventDAOMongo` already wired into
  `EventService`. Purge / sample state therefore matches the router's view and
  dirty-tracking notifications still fire. The reset/rebind lifecycle is
  documented on `Persistence` (`c2a4ec4`).
- **Additive, off the SSF wire** — no `StreamConfiguration` or wire change.
  New coverage: `TestOpenPersistence_EventDAO_LiveInstance` (memory,
  `factory_test.go`) drives an event to delivered state through
  `p.EventService` and observes it via `p.EventDAO`, then runs
  `NewRetentionEngine(p.EventDAO)` `SampleOccupancy` + `PurgeExpired` against
  the live store; `TestGetEventDAO_LiveInstance` (mongo) asserts the same
  write-visibility.

## Cross-repo seam self-check (`make seams`)

- **New `make seams` target** (PR #231, merge `f3ff639`; `28528a3`) — the
  family-consistent cross-repo seam self-check, finishing the canon-migration
  for this repo (design canon + coordination plane live in the family planning
  repo; community is a peer implementation repo). community is a dependency
  *root*, so the wide-workspace check degenerates to `use .`: the target spins
  up an **ephemeral** `go.work`, builds the module through it, then deletes
  it. `go.work` is never committed — the git-tag pin stays the single source
  of truth (ADR 0048) — and a `.gitignore` guard (`/go.work`, `/go.work.sum`)
  makes accidental commits impossible.
- **`go vet` promoted to a hard gate** (`0bc62f9`). Initially advisory because
  of documented pre-existing generated-code diagnostics; once those were fixed
  (below), vet became load-bearing in `make seams` alongside `go build`.
- No canon-reference repointing was needed: a scan found no reference naming
  another repo as design canon, and community (the only public repo) links no
  private planning URLs.

## Vet cleanup + dependency refresh

- **Duplicate json-tag collisions cleared** (`1ffb5d6`). The anonymous embeds
  in `pkg/ssfModels.OneOfSimpleSubject` (8 subject types all promoting
  `json:"format"` / `json:"iss"`) and `pkg/goScim/resource.ScimResource`
  (`User` + `Group`, colliding on `json:"displayName"`) are now **named
  fields**. *Compat note for Go embedders:* field promotion through these
  wrappers no longer applies — write `s.Email.Format` instead of the promoted
  `s.Format`. Neither wrapper is used on the SET wire path (SET subjects are
  built from the concrete subject types), so protocol payloads are unaffected.
- **Keyed `bson.E` fields in cluster-monitor** (`edae44d`) — vet fix in
  `cmd/cluster-monitor`'s `replSetGetStatus` call; no behavior change.
- **Dependency refresh** (`ec2e06b`) — `go get -u ./...` bump of direct and
  indirect Go dependencies; build and tests green on the refreshed set.
- With these, `go vet ./...` is clean module-wide for the first time on this
  branch.

## Keycloak substrate pin 26.6.4

- **#232 — bump the Keycloak substrate pin 26.4.7 → 26.6.4** (PR #233, merge
  `a3f156c`; `1f431ce`). Community share of the family-wide lockstep round
  (coordination anchor planning #31). All six compose pin sites now run
  `quay.io/keycloak/keycloak:26.6.4` (`docker-compose.yml`, `-cluster`,
  `-dev`, `-cluster-dev`, `-spiffe`, `-spiffe-dev`); a repo-wide grep confirms
  no other pin sites.
- **Realm import verified on 26.6.4**: `gosignals-realm.json` imports clean
  (`Import finished successfully`, zero WARN/ERROR/deprecation lines), and the
  26.5/26.6 migration guides document no realm-export field renames.
- **Upstream finding relayed to the family**: Keycloak 26.6.0 changed the
  dev-mode `http-host` default from all-interfaces to `localhost`. Community
  is unaffected (all six compose files already set
  `QUARKUS_HTTP_HOST: 0.0.0.0`); sibling repos should confirm they override it
  too, or a `start-dev` Keycloak becomes unreachable from other containers.
- `docs/keycloak-ssf-guide.md` was deliberately left untouched — its `26.4.0`
  references describe the external `keycloak-ssf-support` PoC repo verbatim,
  not this repo's pin. A separate doc-only cleanup covers the one real drift
  (a stale "latest release" table row).

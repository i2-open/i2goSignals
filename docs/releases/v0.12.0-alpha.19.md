# goSignals v0.12.0-alpha.19

Released: TBD

Compare: [v0.12.0-alpha.18...v0.12.0-alpha.19](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.18...v0.12.0-alpha.19)

## Why this release

A build-infrastructure hotfix. `v0.12.0-alpha.18` was cut and tagged across the
family, then failed the release-QA gate before a single scenario ran: the admin
image would not build, because that repo's Dockerfile still pinned a Go 1.26
builder while the alpha.18 re-pin had raised its module floor to Go 1.27. Tags
are immutable, so the remedy is this new alpha rather than a retag.

There are **no source changes in community** in this window. The only edit here
is a stale Go builder pin of the same class as the one that blocked admin, found
by auditing every `golang:` base image in the family rather than only the one
that happened to fail.

Everything alpha.18 shipped still applies unchanged, including the `crypto.Signer`
migration, the removal of `SecurityEventToken.IsBefore`, and the algorithm
allow-list on `goSet.Parse`. See the alpha.18 notes for the migration detail; if
you are moving from alpha.17 or earlier, read those first.

## Build

- `conformance/Dockerfile.conformance` — builder raised from `golang:1.26.5-bookworm`
  to `golang:1.27-bookworm`. This image compiles the module from the working tree
  (unlike the shipping `Dockerfile`, which copies pre-staged binaries and never runs
  the Go compiler), so it was subject to the same unsatisfiable module floor that
  blocked admin. It is exercised by `docker-compose-conformance.build.yml` and was
  not in the release-QA path, so it had not yet failed anything.

## Known stale pins, deliberately untouched

Two Dockerfiles in this repo carry ancient Go builder pins and are **unreferenced**
by any compose file, Makefile target, or workflow:

- `Dockerfile.multistage` — `golang:1.19`, untouched since 2023.
- `pkg/goSignals/Dockerfile` — `golang:1.10`, pre-modules, only ever renamed.

Neither is bumped here. Bumping a dead file is theatre and deleting one does not
belong in a release train; removal is tracked separately.

# goSignals v0.12.0-alpha.9

Released: TBD
Compare: [v0.12.0-alpha.8...v0.12.0-alpha.9](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.8...v0.12.0-alpha.9)

## Why this release

Where alpha.8 exposed the business-stream event router and metering hook as a
reusable embedding seam, alpha.9 hardens the **receive side** of that data
plane — how a stream decides to trust an inbound SET, and how a receiver builds
the TLS trust pool it uses to reach a transmitter's issuer. Both changes are
additive and default-off, and flag-off / unchanged-config streams are
byte-for-byte unchanged.

The headline is a per-stream **signing-only receive posture** (#184, PR #222):
a `signingOnly` flag that makes the SET's JWS signature — not a transport bearer
— the trust gate on a `purpose: business` receive stream. The bearer becomes
optional across all three receive transports (RFC 8935 push, RFC 8936
poll-as-receiver, and SSTP) while signature verification of inbound SETs becomes
mandatory; any bearer that *is* presented must still be valid. This is the
Model A single-issuer shape: a signing-only stream must carry both an issuer
(`Iss`) and an issuer JWKS URL as its single trust anchor. It supersedes the now
abandoned signing-only *control-stream* line (enterprise #41 `wontfix`; admin
#206/#208 moot) — signing-only is a business-stream concept, not a
control-stream one.

The companion is a receiver TLS trust-pool fix (#220, PR #221). The receiver's
per-server TLS path (`GetTlsConfigForServer`) had diverged from the admin
reference implementation: with no per-server certificate it returned a TLS
config carrying system roots only and never loaded the global/dev CA pool, so a
client-credentials token POST to a private-CA issuer (e.g. a Keycloak behind
`ca-cert.pem`) failed `x509: certificate signed by unknown authority`, surfacing
as an HTTP 500 on credential `PUT /server/{alias}`. The fix seeds `RootCAs` from
the global cert pool and *appends* per-server certs rather than replacing them,
clearing the receiver-side blocker for admin #271 (credential propagation). The
family continues to ship byte-matched at the tag (`v0.12.0-alpha.9`).

## Per-stream signing-only receive posture

- **#184 — per-stream signing-only business-stream receive posture** (PR #222,
  merge `81c2b1a`). New `StreamConfiguration.SigningOnly` flag (default false),
  settable at create/update. Create/update **reject** `signingOnly` unless both
  `Iss` and `IssuerJWKSUrl` are set — the single-issuer trust anchor (Model A).
- **Bearer-optional / signature-required** across all three receive transports.
  The SET's JWS signature is the trust gate; a presented bearer is still held to
  the full stream + scope check, but a *missing* bearer no longer rejects on a
  signing-only stream.
  - **Push (RFC 8935):** when no bearer is presented on a signing-only stream,
    the handler resolves the stream from the path (`/events/{id}`) instead of
    from the token.
  - **SSTP:** the `sstpAuthorized` gate is bypassed only when no bearer is
    presented on a signing-only pair; per-SET errors report via `setErrs`.
  - **Poll-as-receiver (RFC 8936):** signature verification is mandatory under
    the posture.
- **Mandatory verification.** `ReceiverConfig.RequireSignature`
  (`pkg/goSetPush`, `pkg/goSetPoll`) makes a nil JWKS or a verify failure a hard
  reject (`jws_signature_failed`) rather than accepting an unverified SET.
  Error taxonomy: `invalid_issuer` / `jws_signature_failed` / `invalid_request`;
  signature failures log at WARN. `aud` validation is unchanged on all
  transports.
- **Design note (status codes).** Push invalid-bearer returns **HTTP 400**
  (`authentication_failed`), not 401 — the RFC 8935 push handler routes all
  §2.4 errors through `WriteDeliveryError` (always 400) and existing tests pin
  it; the literal 401 is the SSTP path. The
  bearer-always-validated-never-bypassed semantic holds on both.
- **Default-off and additive.** Flag-off streams are byte-for-byte unchanged.
- **Deferred:** multi-issuer allowlist + strict-mode circuit-breaker
  (drop/quarantine on repeated signature failure).

## Receiver TLS trust-pool fix

- **#220 — receiver per-server TLS path never loaded the global/dev CA** (PR
  #221, merge `63b1499`). `GetTlsConfigForServer`
  (`pkg/oauthClient/tls_helpers.go`) now seeds `RootCAs` from the global cert
  pool (`tlsSupport.GetGlobalCertPool`) and **appends** per-server certs instead
  of replacing them, mirroring the admin reference implementation.
- **Fixes** the `x509: certificate signed by unknown authority` → HTTP 500 on
  credential `PUT /server/{alias}` against a private-CA (Keycloak) issuer, and
  clears the receiver-side blocker for admin #271 (credential propagation).
- **Out of scope / deferred** per the issue's framing: Leg B (inbound JWKS) per-
  server parity, transmitter/receiver host conflation, and update-validation
  strictness.

## Related

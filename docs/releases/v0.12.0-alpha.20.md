# goSignals v0.12.0-alpha.20

Released: TBD

Compare: [v0.12.0-alpha.19...v0.12.0-alpha.20](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.19...v0.12.0-alpha.20)

## Why this release

A throughput release. Two performance programs land together: spec #102
(profiling-driven runtime optimization: pooled connections, batched reads and
acks, worker pools, ES256 signing, missing Mongo indexes) and spec #111 (the
ingest and delivery throughput program, Stages 0–3: one-trip writes,
pipelined delivery, concurrent poll claims, and an opt-in local WAL). A
cluster fix batch (#347–#350) closes the cross-node hand-off and
stream-table gaps that the two-node benchmark exposed. Alongside them,
spec #80 sets a TLS floor on business streams, and a run of key-lifecycle
fixes makes signing keys behave correctly across rotation, expiry and nodes.

This alpha has several **behaviour changes operators and clients must
act on**:

- **Streams no longer create signing keys** (#314). Create the issuer key
  first with `POST /key/{issuer}?alg=` (`goSignals create key --alg`), then
  the stream. A signing transmitter with no active key is refused on save
  (#308). `force=replace` now replaces only the named algorithm's keys.
- **Generated keys now expire** (#318). The default lifetime is 180 days
  (`I2SIG_ISSUER_KEY_LIFETIME`; `0` or `never` turns expiry off). Existing
  key records have no dates and never expire. There is no backfill.
- **Outbound business dials must be `https`** (#322, spec #80) unless the
  stream sets `tx_allow_plaintext`. The `I2SIG_INSECURE_SSTP_HTTP`
  environment gate is retired.
- **Push and SSTP ingest answer `503` + `Retry-After`**, not `400`, when the
  store cannot durably accept a SET (#333).
- **Compose stacks moved to PostgreSQL 18 and Keycloak 26.7.3** (PR #295).
  The postgres volume now mounts at `/var/lib/postgresql`, the Keycloak env
  vars use their `KC_*` names, and the dev admin host port is 8081. The
  bootstrap realm now seeds the `operator` role that admin requires (#344).

Mongo 8.0 is now the target: one-trip ingest uses the 8.0 multi-namespace
`bulkWrite` and falls back on older servers (ADR 0043). All compose beds pin
`mongo:8.0.13`. The default durability contract is unchanged: every
acknowledged SET is majority-journaled (ADR 0038). Local WAL durability is
opt-in per stream and refuses to start on a multi-node cluster (ADR 0045).

## Ingest and delivery throughput (spec #102)

- Batched SSTP and poll ingest, parallel SET verification, pooled push
  connections (PR #283).
- Concurrent write of the event body and its delivery intents (#286,
  ADR 0038); per-event stream, revocation and lease lookups cached (#287,
  ADR 0039).
- Indexes on `pendingEvents`/`deliveredEvents` `{sid,jti}` and `{jti}`, built
  on every start, not only for a new database (#288).
- Pooled SSTP dialer HTTP transport, so cycles stop re-handshaking TLS (#289).
- Push: per-stream worker pool over batched reads and acks (ADR 0035);
  concurrency derived from `GOMAXPROCS` (#285, ADR 0037,
  `I2SIG_PUSH_CONCURRENCY`).
- Poll: responses assembled from one read and signed by a worker pool
  (ADR 0036); duplicate poll ack dropped.
- ES256 selectable per stream for SET signing (#284, ADR 0041).
- JWKS background refreshers end when a receiver cache entry is dropped (#290).
- Community's keep-forever event retention documented and logged at
  startup (#291).
- Measured on the dev bed: push about 38 → 536–589 ev/s, poll 162 → 692 ev/s,
  SSTP 292/311 → 579/715 ev/s.

## Ingest and delivery throughput (spec #111, PR #345)

- **Stage 0 — measure.** EventDAO latency and batch-size histograms (#328);
  concurrency sweep, journal-sync counters and block profiles in
  `goSignalsBench` (#329). Baseline in `docs/perf/throughput-baseline-alpha20.md`.
- **Stage 1 — fewer round trips.** Group-commit decorator on EventDAO writes
  (#330, `I2SIG_STORE_GROUP_COMMIT_WINDOW` / `_MAX`); events and pending in one
  `bulkWrite` with a pre-8.0 fallback (#331, ADR 0043); per-collection write
  concern, events/pending majority and delivered `w:1` (#332); `503` +
  `Retry-After` on ingest store failure (#333, `I2SIG_INGEST_RETRY_AFTER`);
  fencing token enforced on acks, runner leases released on stop, expired
  lease reads as unowned (#334).
- **Stage 2 — pipelining.** One-trip ack (#335); send decoupled from ack, with a
  bounded in-flight set and coalescing acker (#336); concurrent RFC 8936 polls
  served from disjoint claims, `returnImmediately` honoured (#337); 2–4
  outstanding polls in the poll receiver (#338); K outstanding pushes and SSTP
  batches per stream (#339, ADR 0044). Data race on concurrent
  `RemoteAddress` persist fixed (#346).
- **Stage 3 — opt-in local WAL.** `I2SIG_STORE_WAL=local` with a drain worker
  (#340, ADR 0045); drain before lease release and replay before ingest on
  restart, with WAL metrics (#341); ring-fed delivery reading the local WAL
  first (#342); per-stream `durability` attribute and the multi-node
  refuse-to-start guard (#343). The WAL is an append-only segment log with one
  fsync per group (ADR 0046).
- Per-leg delivery latency in the bench, and an event-age-at-receipt
  histogram on the router (#325). `toe` keeps sub-second precision across
  hops.
- New knobs are listed in `docs/configuration_properties.md`; per-slice
  measurements are under `docs/perf/`.

## Cluster

- Level-triggered cross-node delivery wake; push and SSTP no longer stall or
  cap at about 100 SETs/s per peer after a dropped wake (#347).
- Per-node advertised wake-up address, `I2SIG_CLUSTER_ADVERTISE_URL`, with a
  warning on duplicates; the cluster composes now set one per node (#348).
- Peers learn of stream create, delete, status and config changes through
  `POST /_cluster/stream-changed` instead of waiting for the 40 s sync (#349).
  The sync now removes streams that are gone, stopping their runners and
  releasing leases; a reaper clears stale node and lease rows (#350).
- A pause or disable now stops a live push runner; a lease takeover never
  overwrites an operator's status (PR #351).
- Poll buffer serves a JTI once per batch; the queued-JTI set is dropped.

## Signing keys

- `POST /key/{issuer}?alg=` accepts `RS256` (default), `ES256` and `ML-DSA-65`;
  create, rotate and replace act on one algorithm (#314).
- A signing transmitter with no active key is refused on save and re-enable.
  Push pauses then disables (#308). Poll and SSTP transmitters do the same
  (#312). Key-unavailable pauses log one ERROR (#313).
- Suspend or replace that would strand signing transmitters answers `409` (#311).
- The key cache expires (2 s) so every node follows a rotate, replace,
  suspend or revoke (#313).
- The newest key is chosen by creation time, not record id, and object ids
  sort in mint order, so a rotated key signs at once (#316). See
  `docs/operations.md`, "Upgrading a store from v0.11.0 through
  v0.12.0-alpha.19".
- Keys carry `not_before`/`not_after`. A key outside its validity never signs,
  and a background check pauses idle streams at key expiry (#318). PEM uploads
  read every block; EC P-256 and ML-DSA-65 certificates are accepted
  (ADR 0042).

## Streams and SSTP

- SSTP pairs carry a per-direction `event_source` (#296), and the pair's
  `event_source` is immutable. `iss`/`aud` accept StringOrURI and only warn on
  shape (#298).
- Per-direction `receive_mode` on the pair bootstrap (#306). Stream update
  accepts `route_mode`, `iss`, `aud` and the issuer JWKS URL.
- Subject-filter review resolves an unset or empty-type `event_source` to
  `DIRECT`, matching the router (#299, #302).
- `stream/list` returns whole records (#300).
- `POST /status` and `PUT`/`PATCH /stream` resolve an SSTP pair's halves per
  direction. Every pair status, including disable, is pair-level. A
  stream-bound token is confined to its bound streams (#303).
- Stream handlers answer `404` only for a missing stream, `400` for a
  rejected update and `500` (with no error text) for a store failure (#305).
- The `tx_alias` credential goes only to the alias host. An unregistered
  `tx_alias` answers `400`. A LOCAL stream is not rejected when its upstream
  cannot be checked.
- Push-runner restart hands off cleanly instead of delivering the old queue
  with old settings (#309). POLL receiver pause and disable stop polling (#310).

## TLS and transport security (spec #80)

- Business-stream TLS floor: push, poll-receiver and SSTP-initiator endpoints
  must be `https` unless `tx_allow_plaintext` is set. This is checked on
  create and update and enforced at every dial. The CLI gains
  `--allow-plaintext` (#322, PR #323).
- Receiver management, verify and status dials are guarded by the same floor
  (#324).
- SPIFFE peer clients share one pooled `X509Source` instead of opening one per
  call. Shutdown, contention, eviction and proxy handling were hardened in
  review (#326).

## Profiling and operations

- Opt-in pprof listener (`I2SIG_PPROF_ADDR`) with mutex and block profiling
  (#292); dev-stack profiling targets (PR #282).
- `goSignalsBench`: an end-to-end load and routing harness with push, poll and
  SSTP legs, a concurrency sweep and per-leg latency, plus
  `docker-compose-benchmark.yml`.
- Transport and streaming research notes in `docs/perf/` (PR #327).

## Build and dependencies

- Compose: `postgres:18-alpine` with the 18+ volume layout, Keycloak 26.7.3,
  `KC_BOOTSTRAP_ADMIN_*` / `KC_HOSTNAME` / `KC_HTTP_HOST`. The Keycloak issuer is
  now always `https://keycloak:9080/realms/gosignals` (PR #295). `mongo:8.0.13`
  is pinned across all beds.
- Bootstrap realm seeds the `operator` realm role for both bootstrap users
  (#344).
- go-jose 4.1.5, mongo-driver 2.9.1, go-spiffe 2.8.2, grpc 1.84.0 (PR #319).
- Two `eventRouter` tests no longer leak a poll or push buffer goroutine, so
  the `make qa` leak check is green again (#354, PR #355).

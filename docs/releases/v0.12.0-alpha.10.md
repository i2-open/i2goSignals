# goSignals v0.12.0-alpha.10

Released: TBD
Compare: [v0.12.0-alpha.9...v0.12.0-alpha.10](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.9...v0.12.0-alpha.10)

## Why this release

Where alpha.9 hardened the receive side of the business-stream data plane,
alpha.10 tightens **key lifecycle**. It replaces the hard-delete of a signing
key with a reversible, auditable status model: a key moves through explicit
lifecycle states rather than disappearing from the store. The change is a single
focused primitive (#223, PR #224, ADR 0028) and the family continues to ship
byte-matched at the tag (`v0.12.0-alpha.10`).

## Key revoke/suspend primitive

- **#223 — revoke/suspend key-status primitive; remove hard-delete route** (PR
  #224, ADR 0028). A key is now lifecycle-managed through explicit status
  transitions — **active → suspended** (temporary, reversible) and **active →
  revoked** (terminal) — instead of being removed from the store. The prior
  hard-delete HTTP route is **removed**.
- **Reconciled across planes.** A status change is reconciled across both the
  **signing** plane and the **verification** plane, so a suspended or revoked key
  stops being used to sign and is no longer trusted to verify — the two views of a
  key never drift.
- **Auditable by construction.** Because keys are transitioned rather than
  deleted, the lifecycle history remains inspectable; a suspended key can be
  returned to active, while a revoked key stays terminal.

## Upgrade notes

- The hard-delete key route no longer exists. Callers that previously deleted a
  key should **revoke** (terminal) or **suspend** (reversible) it instead.

## Related

- ADR 0028 records the key-status lifecycle decision (revoke/suspend over
  hard-delete) and the cross-plane reconciliation contract.

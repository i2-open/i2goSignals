# goSignals v0.12.0-alpha.5

Released: TBD
Compare: [v0.12.0-alpha.4...v0.12.0-alpha.5](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.4...v0.12.0-alpha.5)

## Why this release

alpha.5 is a **discovery-correctness** release. alpha.4 delivered the
transmitter-side identity model (PRD #196); this release hardens the
`.well-known` discovery surface that a strict SSF receiver — the OpenID
conformance suite is the canonical example — fetches before it will trust a
transmitter. Three areas land together: a strict provisioning posture for the
standalone `cmd/goSsfServer` simulator so its declared issuer always resolves
(PR #206, ADR 0025), enforcement of the SSF §7.2.4 issuer↔discovery-location
binding when a peer is strict (PR #208, issue #207), and a correctness fix to
SSF §7.2.1 foreign-issuer discovery plus a precise gate on the legacy
`sse-configuration` fallback (PR #210, issue #209).

The same window also tidies the OAuth metadata story. OAuth fields
(`authorization_servers`, `scopes_supported`, `bearer_methods_supported`) that
never belonged in the SSF Transmitter Configuration document are dropped from
it — RFC 9728 Protected Resource Metadata remains their home — and a new RFC
8414 endpoint, `/.well-known/oauth-authorization-server[/{issuer}]`, fills the
gap left behind: it reflects the configured external authorization server
verbatim as a discovery proxy, or serves goSignals' own partial AS surface when
no external AS is configured (PR #210, ADR 0026).

Compatibility: stream-management and goSignals-to-goSignals cluster federation
are unchanged. The new strict behaviors are all opt-in / posture-gated — the
`goSsfServer` strict mode is off by default (`I2SIG_STRICT_SSF`), and the
§7.2.4 binding check keys off the per-peer `StrictSsf` flag (warn-and-continue
under the flexible default, fail only under strict). The wire-visible change is
the trimmed Transmitter Configuration document; any consumer that read the
OAuth fields off the SSF discovery doc must move to RFC 9728 PRM or the new RFC
8414 endpoint. This release continues the SHA→tag release train: the family
pins goSignals by tag (`v0.12.0-alpha.5`).

## Strict-spec SSF transmitter mode for `goSsfServer` (PRD #196, ADR 0025)

PR #206 adds an opt-in, **off-by-default** posture — `I2SIG_STRICT_SSF` — scoped
to the standalone `cmd/goSsfServer` simulator, a PRD #196 follow-up.

- **Opt-in posture switch.** `services.StrictSsfEnabled()` reads
  `I2SIG_STRICT_SSF` (truthy = `true` / `1` / `enabled` / `yes`); off by
  default. `cmd/goSignalsServer` (the full cluster server) does **not** consult
  it, and the `/stream` registration contract is unchanged for both binaries —
  stream creation stays ADR 0024 presence-based everywhere.
- **Deterministic issuer provisioning.** On startup `cmd/goSsfServer` calls
  `SsfApplication.ProvisionStrictMode`, which requires an
  administrator-declared `I2SIG_ISSUER_DEFAULT` as an explicit absolute
  `http(s)` URL (the base-URL / `DEFAULT` fallback is refused, fail-fast), then
  idempotently provisions that issuer's SET-signing key via the new
  `KeyService.EnsureSigningKey`. Unlike `InitializeTokenKey`'s first-init-only
  seeding, `EnsureSigningKey` is restart-safe, so an issuer added to an
  established deployment still resolves.
- **One issuer, three resolutions.** Strict mode binds `iss` == discovery
  issuer == JWKS key name (ADR 0023): `/.well-known/ssf-configuration/<path>`
  (RFC 8615 path insertion), `/jwks/<path>`, and SET signing all resolve under
  the one declared issuer, so a strict receiver's "`iss` equals discovered
  issuer" check passes.
- **`I2SIG_STRICT_SSF` documented** in `docs/configuration_properties.md`.

See [ADR 0025](../adr/0025-strict-ssf-transmitter-mode.md).

## SSF §7.2.4 issuer↔discovery-location binding (#207)

PR #208 enforces the SSF §7.2.4 binding in both places goSignals fetches
transmitter discovery: a transmitter's advertised `issuer` MUST equal the
location its `.well-known/ssf-configuration` document was retrieved from — the
symmetric counterpart of the conformance suite's
`OIDSSFCheckTransmitterMetadataIssuer`.

- **`EvaluateIssuerBinding(metadataIssuer, discoveryLocation, strict)`** added
  to `pkg/wellKnownSupport`. Scheme/host comparison is case-insensitive and
  trailing-slash-tolerant.
- **Keyed off the per-peer `StrictSsf` posture** (`SsfServer.StrictSsf` /
  `model.Server.StrictSsf`), **not** the `goSsfServer`-only `I2SIG_STRICT_SSF`
  env flag (which stays scoped per ADR 0025). Flexible (default) → **warn** and
  continue (server/stream still recorded); strict (`--strict-ssf` /
  `StrictSsf=true`) → **fail**, aborting the add / registration.
- **Wired into both fetch sites.** `add server` (`cmd/goSignals/commands.go`)
  compares `transmitterConfiguration.Issuer` to `server.Host`; receiver
  `CreateStream` (`pkg/services/stream_service.go`) compares `txConfig.Issuer`
  to `txServer.Host`.
- **`jwks_uri` stays free-form** — deliberately excluded from the check (it
  isn't even a parameter, so the coupling can't be reintroduced); a `pkg/goSet`
  regression confirms a free-form `jwks_uri` on an issuer-unrelated path is
  fetched verbatim and its keys load.
- **Policy-free primitives exported** — `IssuerMatchesLocation` /
  `IssuerBindingDetail` — so callers can compute the §7.2.4 verdict without the
  warn/fail policy baked in. These are consumed by the admin discover probe
  (admin #241).
- **Deviation:** a discovery *fetch* failure keeps its existing hard-fail in
  both modes (a nil `ServerConfiguration` is unsafe to record — downstream
  commands dereference it); only the issuer *mismatch* case is warn/fail-by-
  strict.

## SSF §7.2.1 foreign-issuer discovery + fallback gating (#209)

PR #210 fixes two discovery defects surfaced by a configured foreign issuer.

- **Foreign-issuer discovery resolution (server).**
  `GET /.well-known/ssf-configuration/{issuer}` previously resolved only
  base-rooted local issuers, while the JWKS handler resolved
  local-rooted-then-bare — so a foreign issuer (e.g.
  `cluster.scim.example.com`) serving keys at `/jwks/<name>` 404'd at
  discovery. A shared `resolveIssuerKeyName` primitive now implements ADR 0023's
  "reconstruct `baseURL + "/" + segment` first, fall back to the bare captured
  name" rule, and **both** the JWKS handler and the discovery handler route
  through it. The discovery handler echoes the resolved issuer **verbatim** as
  `issuer` (SSF §7.2.4), never the base-rooted form.
- **`sse-configuration` fallback gated on a primary 404 (client).**
  `FetchSSFConfiguration` / `CheckSSFConfiguration` previously fell back to the
  legacy `sse-configuration` path on **any** primary error, masking the real
  failure behind a fabricated-URL fallback error. A typed `HTTPStatusError`
  now carries the HTTP status so `isNotFound` can gate precisely: the fallback
  engages **only on a primary HTTP 404**; transport/decode/non-404 errors
  surface the primary `ssf-configuration` error directly, and a failed fallback
  still wraps (`%w`) the primary failure.

## OAuth Authorization Server Metadata (ADR 0026)

- **Non-spec OAuth fields dropped from `TransmitterConfiguration`.** PR #210
  removes `authorization_servers`, `scopes_supported`, and
  `bearer_methods_supported` from the SSF Transmitter Configuration document,
  where they never belonged — RFC 9728 Protected Resource Metadata at
  `/.well-known/oauth-protected-resource` remains their home. Any consumer that
  read these off the SSF discovery doc must move to RFC 9728 PRM (or the new RFC
  8414 endpoint below).
- **New RFC 8414 endpoint.**
  `/.well-known/oauth-authorization-server` and
  `/.well-known/oauth-authorization-server/{issuer:.+}`, keyed off whether an
  external authorization server is configured (`AuthIssuer.GetOAuthServers()`):
  - **External AS configured → reflect it verbatim (discovery proxy).**
    goSignals fetches the configured AS's RFC 8414 document
    (`oauth-authorization-server`, falling back to the OpenID Provider
    `openid-configuration` — Keycloak serves both) and returns the raw JSON
    unmodified (`json.RawMessage`, lossless passthrough). The client learns the
    real AS's `issuer`, `authorization_endpoint`, and `token_endpoint` and
    talks to it directly. An unreachable upstream returns `502`.
  - **No external AS configured → serve goSignals' own partial AS surface** for
    the bearer tokens it mints itself (stream-management / rotate-on-GET tokens,
    ADR 0022): `/introspect`, `/revoke`, `/register`, and its JWKS. goSignals
    has no `authorization_endpoint` / `token_endpoint` of its own.

See [ADR 0026](../adr/0026-oauth-authorization-server-metadata-proxy.md).

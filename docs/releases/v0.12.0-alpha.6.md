## Why this release

alpha.6 is a **lockstep leaf tag**. The i2gosignals family ships as one release
train — a single `v0.12.0-alpha.N` version tagged on every repo each PRD round
(ADR 0048) — and community is the leaf the rest of the family pins by tag. This
round community carries **no functional code change**: the
`v0.12.0-alpha.5..HEAD` window holds only the alpha.5 release merge, and the
diff against `v0.12.0-alpha.5` is empty. The version moves so the family stays
in lockstep, nothing more.

The substantive alpha.6 work lands in the sibling repos:

- **tenancy** — PRD #7 lifecycle-directives **joint e2e** (#80). Flow B
  (multi-subject realm) is green against community + enterprise + admin peers
  pinned at this train's tag; Flow D (server-replaced fan-in) is unblocked by
  the admin fix below.
- **admin** — **result-txn correlation** fix (#246, PR #247): a lifecycle
  result envelope now correctly echoes the originating directive's transaction
  id, so the receiver can correlate result⇄directive.

Compatibility: community's SSF/SSTP wire surface, stream-management, and
goSignals-to-goSignals cluster federation are **unchanged** from alpha.5. There
is no wire-visible delta in this repo. The family pins community by tag
(`v0.12.0-alpha.6`), continuing the SHA→tag release train.

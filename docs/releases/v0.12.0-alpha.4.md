# goSignals v0.12.0-alpha.4

Released: TBD
Compare: [v0.12.0-alpha.3...v0.12.0-alpha.4](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.3...v0.12.0-alpha.4)

## Why this release

alpha.4 delivers **strict-mode SSF transmitter** support (PRD #196). alpha.3
brought goSignals into OpenID SSF 1.0 conformance; this release adds the
transmitter-side behavior a *strict* SSF receiver — the OpenID conformance
suite is the canonical example — requires to register and validate a stream
without supplying transmitter-owned fields. Three correctness changes land
together: presence-based acceptance of `iss`/`aud` with transmitter-assigned
identity when they are absent (ADR 0024), `EventSource`-aware routing so a
minted audience actually routes events, and a guarded Publish-mode re-sign that
no longer corrupts or races the shared event token under concurrent fan-out.

Compatibility: goSignals-to-goSignals cluster federation is unchanged. Strict
posture is **operator-declared, never auto-detected** — a new `StrictSsf` flag
on the server record, default `false` (flexible), so existing deployments keep
the prior behavior until they opt in. The one wire-visible default change is the
shape of a transmitter stream's auto-assigned `aud` (now an opaque
`urn:i2-open:ssf:aud:<ksuid>` instead of the caller's `client_id`/`project_id`);
any consumer that read the old echoed value as a caller handle must not rely on
it. One SCIM event-type URN was also corrected to canonical lowercase (see
below). This release continues the SHA→tag release-train migration: the family
now pins goSignals by tag (`v0.12.0-alpha.4`) rather than by raw commit SHA.

## Strict-mode SSF transmitter (PRD #196)

The PRD landed as six slices (#198–#203) under PR #204.

### Transmitter-assigned identity (ADR 0024)

- **Presence-based `iss`/`aud` acceptance on `/stream` create.** A
  caller-asserted `iss` or `aud` is honored verbatim; an absent one is **minted**
  by the transmitter. Presence is never overridden by minting, and minting never
  happens when the caller asserted intent — so a strict receiver can register
  without supplying either, while a flexible peer (goSignals cluster sisters)
  keeps its explicit values. See
  [ADR 0024](../adr/0024-transmitter-assigned-identity.md).
- **Minted `iss` = the server's advertised issuer** (`GetDefIssuer()`), the same
  `issuer` returned in the `.well-known` Transmitter Configuration, so the strict
  receiver's "`iss` equals discovered issuer" check (SSF §8.1.1) passes with no
  special case. A per-stream `iss` is explicitly ruled out by SSF §8.1.1.1; every
  transmitter stream signs under the one advertised issuer.
- **`jwks_uri` derives from that issuer** (`baseURL + /jwks.json`, the same JWKS
  the metadata advertises, per ADR 0023). Derivation is gated on the minted-issuer
  case; a caller-asserted *foreign* `iss` is left untouched.
- **Minted `aud` = a fixed, immutable, opaque, URI-shaped identifier**
  (`urn:i2-open:ssf:aud:<ksuid>`), generated once at create, persisted on the
  stream, and stable for its lifetime. It does **not** leak the caller's
  `client_id` / `project_id`, and doubles as the AUDIENCE routing handle (below).
- **Receiver streams (`…:receive`) are unaffected** — they connect to a foreign
  transmitter, so the prior `client_id` → `project_id` default for an absent `aud`
  remains the most specific stable local identity.

### EventSource-aware routing

- **`MatchesStream` now honors the `EventSource` routing axis** (ADR 0004), so a
  transmitter-assigned `aud` routes events even when the inbound event's `aud`
  differs:
  - **DIRECT** (or a nil/unset `EventSource`) keeps the historical
    `(iss, aud, event-type)` filter unchanged.
  - **AUDIENCE** treats the stream's own `aud` as the routing handle and no longer
    requires the inbound event's `aud` to equal it (`iss` and event-type filters
    still apply) — this stops a minted `aud` from silently black-holing delivery.
  - **EXPLICIT** matches when the inbound event's origin stream id
    (`EventRecord.Sid`) is named in `EventSource.SourceStreamIds`.
- **Issuer rule:** `iss` matching is mandatory for Forward (FW) mode and ignored
  for Publish (PB) mode; other modes keep the historical empty-as-wildcard
  behavior. `RemoteStreamId` is never consulted as a routing selector.

### Guarded Publish-mode re-sign

- **PB re-sign now copies the event token before mutation.** Publish-mode
  re-signing previously mutated the shared in-memory event token in place,
  corrupting state and racing under concurrent multi-stream push fan-out — two
  streams could sign with each other's `iss`/`aud`. The path now takes a value
  copy of the `SecurityEventToken` before setting `iss`/`aud`/`iat`/`kid`, so each
  stream signs under its own identity and the stored event stays pristine.
- **`jti` and `txn` are preserved verbatim** across the hop (ADR 0017); they are
  carried by the copy and never touched. FW mode continues to emit
  `Event.Original` bytes verbatim with no re-sign.

### Operator-declared strict posture

- **`StrictSsf` is now a field on `model.Server`** (json/bson tags, default
  `false` = flexible). The full-struct decode in `CreateServer` / `ServerUpdate`
  and the DAO `DeepCopy` carry it through `POST /server` and
  `PUT /server/{alias}` with no new wiring. Default-off preserves
  goSignals-to-goSignals cluster federation; posture is operator-declared only,
  never auto-detected (ADR 0024).

## CLI and shared model

- **`StripTransmitterSupplied` lifted to `pkg/ssfModels`** as a pure, exported,
  table-tested helper, with both production callers wired to it (no duplicate
  logic).
- **CLI warn-and-drop on strict registration.** When registering against a strict
  server, `executeCreateRequest` now drops an operator-asserted
  `iss` / `aud` / issuer JWKS URL with a user-visible message (SSF §8.1.1.1
  — these are transmitter-supplied).
- **Receiver-side create-stream applies the strict posture.** The handler
  resolving a `TxAlias` reads `StrictSsf` off the resolved server record and calls
  the shared helper before POSTing on both the poll and push publisher-leg paths.

## Event-type correction

- **SCIM async-response event URN corrected to canonical lowercase**
  (`urn:ietf:params:scim:event:misc:asyncResp` →
  `urn:ietf:params:scim:event:misc:asyncresp`). Clients keying off the prior
  mixed-case value must update to the canonical form.

## Conformance harness and tooling

- **Strict-mode SSF transmitter conformance e2e** added (#203) — exercises
  registration + delivery against the strict-receiver expectations end-to-end.
- **Archive-run step** (`conformance/archive-run.sh`) collapses `results/` down to
  a single `run-<ts>-archive.zip` plus a copy of the latest summary, wired in as
  the final step of `make all` and `make full` so `results/` stays legible
  run-over-run. Safe no-op when there is nothing to bundle; leaves `.gitignore`,
  prior archives, and subdir snapshots untouched.
- **Preflight reachability checks** in `run-plan.sh` / `run-receiver-plan.sh`
  verify suite-to-SUT connectivity before a run, surfacing networking failures up
  front instead of silently. A `check-suite-reaches-sut.sh` guard and a
  `suite-overlay.yml` (`host-gateway` wiring for `localhost.emobix.co.uk`) were
  added, plus a global findings aggregator in `run-all-plans.sh` that reports
  per-module non-PASS details in the summary. Receiver plan variants were updated
  for suite v5.1.45 (`ssf_auth_mode=static`).

## Documentation

- **`CLAUDE.md` minimized** — build / test / run / Delve commands and Go
  conventions stay; cross-repo, workflow, and agent-skills content moved to the

  corrected (`StreamEventMatch` → `EventService.MatchesStream`; the
  `pushEvent` → `prepareAndSendEvent` → `delivery.PushDelivery` push chain).

# goSignals v0.12.0-alpha.16

Released: TBD
Compare: [v0.12.0-alpha.15...v0.12.0-alpha.16](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.15...v0.12.0-alpha.16)

## Why this release

**Essentially a train-alignment retag, with two small changes that landed during
the train itself.** The family ships one version across all five code repos each
round, so community takes the new tag to stay aligned. `v0.12.0-alpha.15` was cut
at `6f3bb70` on 2026-07-28 and nothing landed on `release-0.12.0` between then
and this train — the alpha.15 tag commit *was* the branch head. The library
surface is unchanged; see *Changes in this repo* below for the two deltas.

Everything described in the [v0.12.0-alpha.15 notes](v0.12.0-alpha.15.md) — spec
**#247** / **ADR 0029** opt-in event validation, the `pkg/goSetValidate` registry,
the per-receiver `event_validation` knob and the `events_requested` /
delivery-path behavior changes — is the current state of community at this tag
too, unchanged. There is no migration step and no compatibility impact in
upgrading a community deployment from alpha.15 to alpha.16.

**What the train is actually for** is work in the sister repos, both of which
consume community unchanged at this tag:

- **admin `#334`** — the admin image could not be built from a clean tag
  checkout (the `Dockerfile` never built the `@independentid/console-ui`
  workspace, and an unanchored `.dockerignore` `dist` pattern hid it on
  developer machines). This aborted the family release-QA run at
  `v0.12.0-alpha.15` before any scenario executed, so alpha.15 was never
  blessable. Fixed and merged in admin **PR #336** (with `#330` and `#335`).
- **tenancy `#286`** — the `suspend-resume` QA scenario asserted a behavior the
  design never promised (probing the unauthenticated customer `/health`); it now
  asserts the ADR-0057 auth freeze on the tenant's own realm. Merged in tenancy
  **PR #287**.

## Changes in this repo

- **Image-level `HEALTHCHECK` default** (`Dockerfile`). A plain `docker run` of
  the server image now gets the same liveness signal the compose files already
  wire per service. It probes through the shipped `/app/healthcheck` binary —
  the chainguard/bash base carries neither curl nor wget — exec'd directly, with
  no shell involved. It targets the default TLS listener with `-k`, because the
  server may present a self-signed or SPIFFE cert. The binary takes a single URL
  and has no scheme fallback, so a TLS-disabled deployment or a non-default port
  must override via `docker run --health-cmd` or the compose `healthcheck` key.
  30 retries at 10s allows a 5-minute grace window for mongo and cluster join.
- **Stale test assertion corrected** (`mongo_provider` suite). `TestB_StreamConfig`
  pinned the advertised catalogue at 26 events; the WISE types added in `d3f5f72`
  took it to 30 (12 SCIM + 5 CAEP + 9 RISC + 4 WISE) without updating the
  assertion. Test-only — no runtime behaviour changes. See *Verification*.
- Version source bumped: `pkg/constants/version.txt` → `0.12.0-alpha.16`.
- No library, protocol, configuration or metrics changes. `pkg/goSet`,
  `pkg/goSetPush`, `pkg/goSetPoll`, `pkg/goSetSstp`, `pkg/goSetValidate` and
  `pkg/ssfModels` are byte-identical to `v0.12.0-alpha.15`.

## Related

- Consumers pinning community by tag (enterprise, admin) may re-pin to
  `v0.12.0-alpha.16` for family alignment; the recompile is a no-op.
- The bundle-format-v3 break recorded against **ADR-0073** in the 2026-07-28
  sequencing is **not** in this tag and lands on a later train.

## Verification

`make build`, `go vet ./...` and `go test -race ./...` (~41 packages) are green
at this tag, with no data races.

Worth recording plainly: `v0.12.0-alpha.15` was **not** green. The stale
`TestB_StreamConfig` assertion above had been failing since `d3f5f72`, which
`v0.12.0-alpha.15` contains, so that tag shipped with a red suite. It went
unnoticed because this repo's `Makefile` exposes only `build` — there is no
`ci`, `test`, `vet`, `lint` or `tidy-check` target, so the release gate has to
be assembled by hand and community's suite had never actually been run by one.
Adding an aggregate gate target here is worth its own issue.

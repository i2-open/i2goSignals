# goSignals v0.12.0

Released: TBD

First full release since [v0.11.1](v0.11.1.md). It consolidates the pre-releases
`v0.12.0-alpha.1` through `v0.12.0-alpha.22`. **This is not a drop-in upgrade:**
the store is migrated one way at first start, and the signing-key and TLS
defaults change. Read [Upgrade](#upgrade) before you start a v0.12.0 server on
an existing store.

## Why this release

v0.11 was a push/poll SET router. v0.12.0 changes five things about it:

- **SSTP is a third delivery method.** A pair of servers exchanges SETs in both
  directions over one authenticated channel (draft-hunt-secevent-sstp), beside
  RFC 8935 push and RFC 8936 poll.
- **It passes OpenID SSF 1.0 final conformance**, as transmitter and as
  receiver, and the conformance harness ships in the repo.
- **Unsigned and unauthenticated SETs are no longer accepted.** Signature
  verification is allow-listed, every business stream needs a trust anchor, and
  outbound dials are `https` unless a stream opts out.
- **Delivery was rebuilt for throughput and for clusters.** One `deliveries`
  collection replaces two, any node answers a poll or SSTP request, and push,
  poll and SSTP run concurrently per stream.
- **Signing keys have a lifecycle.** Keys are created explicitly, expire, can be
  suspended or revoked, and may be ES256 (the new default), RS256 or
  post-quantum ML-DSA-65.

It also moves the build to Go 1.27.4.

## SSTP delivery

- New transfer method: `POST /sstp/{id}` carries SETs and acknowledgements both
  ways between two paired servers. One pair record holds both directions
  (ADR 0018), created with `goSignals create stream sstp` or a
  `--bootstrap-file` (ADR 0019). See `docs/SSTP.md`.
- New library `pkg/goSetSstp`: `Exchange`, request/response parsing, `VerifySET`
  / `VerifySETX5C`, a per-SET error registry (`ClassifySetErr`,
  `PartitionSetErrs`) and the problem types `ProblemBindingRevoked` and
  `ProblemServerSuspended`.
- Acknowledgement is literal: only the JTIs a peer names are acked. Per-SET
  errors travel in `setErrs`; an unregistered error code is held, not dropped.
  A signing error halts the stream.
- An inbound SSTP stream in `FORWARD` or `PUBLISH` mode routes onward
  (ADR 0031). Set `IMPORT` to stop at this server.
- The pair's `event_source` and `receive_mode` are set per direction at
  create. `event_source` cannot be changed afterwards. Pair status changes,
  including disable, apply to the pair.
- In a cluster the acceptor holds a lease and any node answers
  (see [Cluster](#cluster)).

## OpenID SSF 1.0 conformance

Wire-level corrections, each visible to a client:

- Stream delete answers `204 No Content` (was `200`).
- PUT/PATCH `/stream` takes its target from the body's `stream_id` when no
  query parameter is given.
- A transmitter always assigns `aud` when the caller omits it: an opaque
  `urn:i2-open:ssf:aud:<uuid>`, fixed at create (ADR 0024). `iss` is the
  server's advertised issuer. A caller-asserted `iss` or `aud` is kept.
- Discovery uses RFC 8615 path insertion
  (`host/.well-known/ssf-configuration/<path>`). Issuers with a path are
  served discovery and JWKS documents (ADR 0023).
- `authorization_servers`, `scopes_supported` and `bearer_methods_supported`
  left the SSF configuration document. Read them from
  `/.well-known/oauth-protected-resource` (RFC 9728) or the new
  `/.well-known/oauth-authorization-server` (RFC 8414, ADR 0026).
- An omitted `events_requested` now means the full supported catalog. Wildcards
  are answered as the enumerated list. A pattern that does not compile is
  `400`.
- With subject filtering enabled, a stream created without `default_subjects`
  starts at ALL instead of dropping every event.
- The SCIM async-response event URI is lowercase:
  `urn:ietf:params:scim:event:misc:asyncresp`.
- As a receiver: deleting a stream deletes it at the transmitter, `aud` and
  `iss` are taken from the transmitter's response, status and verify calls
  carry `stream_id`, a string-valued `aud` is accepted, and per-stream
  transmitter TLS settings apply to every outbound call.
- `POST /trigger-event` is implemented and delivers only to the streams the
  request names.

Strict mode (ADR 0025): mark a peer `--strict-ssf` to drop operator-asserted
`iss` / `aud` when registering with it and to fail when its advertised issuer
does not match where its configuration was fetched (SSF §7.2.4). The default
only warns. `I2SIG_STRICT_SSF` applies to `cmd/goSsfServer` alone.

The harness is under `conformance/`: 4 transmitter and 4 receiver plans, driven
by `run-all-plans.sh`.

## Security

- **Signatures are required.** `goSet.Parse` returns an error without a JWKS;
  use the new `goSet.Peek` to inspect an untrusted token. The `alg: none`
  branch is gone. Accepted algorithms are `RS256`, `ES256` and `ML-DSA-65`;
  `PS256`, `RS512` and HMAC variants are rejected at the header.
- **Every business stream needs a trust anchor:** a bearer or mTLS, or an
  issuer plus issuer JWKS URL. At startup a stored receiver stream with
  neither is disabled.
- **Signing-only receive** (per stream, off by default): the signature is
  required and the bearer optional. It needs both `iss` and the issuer JWKS
  URL.
- **Outbound TLS floor.** Push, poll-receiver and SSTP dials, and receiver
  management calls, must be `https` unless the stream sets
  `tx_allow_plaintext` (CLI `--allow-plaintext`). `I2SIG_INSECURE_SSTP_HTTP`
  is retired. Every TLS config sets TLS 1.2 as its minimum.
- **Credentials are masked.** Stream credentials read as `***` on every GET.
  The live value appears only in create and rotation responses; a client that
  read credentials back from a GET must change.
- **Bearer rotation** (ADR 0022, off by default):
  `I2SIG_BEARER_ROTATE_ON_GET` mints a replacement when a stream is read with
  its own bearer; the old one stays valid for `I2SIG_BEARER_ROTATE_GRACE`
  (default 1h).
- **Post-quantum.** ML-DSA-65 SET signing per stream (ADR 0034, RFC 9964). A
  SET grows from about 1.1 KB to 5.2 KB. TLS key exchange offers
  `X25519MLKEM768`; `I2SIG_TLS_PQ_KEM=MLKEM1024` adds ML-KEM-1024. The FIPS
  140-3 module v1.0.0 cannot do ML-DSA.
- **Issuer JWKS** fetches retry, and each stream reports `jwks_readiness`
  (ADR 0033).
- A stream-bound token is confined to its streams. Project ids are minted from
  `crypto/rand`. A private-CA issuer no longer fails with
  `certificate signed by unknown authority` on `PUT /server/{alias}`.
- A fix with security weight: under concurrent fan-out, Publish-mode re-signing
  could sign one stream's SET with another stream's `iss` / `aud`.

## Signing keys

- **Streams no longer create keys.** Create the issuer key first with
  `POST /key/{issuer}?alg=` (`goSignals create key --alg`), then the stream.
  A signing transmitter with no active key is refused on save; a running one
  pauses, then disables.
- **New keys are ES256** (ADR 0041). `I2SIG_KEY_ALG` selects `ES256`, `RS256`
  or `ML-DSA-65`; any other value stops the server at startup. The auth-token
  key stays RSA.
- **The newest active key decides the SET `alg`** for a stream with no
  `signing_alg`. Creating a key therefore switches those streams. Pin
  `signing_alg` on a stream whose receiver cannot follow.
- **Keys expire** (ADR 0042): 180 days by default
  (`I2SIG_ISSUER_KEY_LIFETIME`; `0` or `never` turns expiry off). Keys that
  existed before the upgrade have no dates and never expire.
- **Hard delete is gone** (ADR 0028). `POST /key/{keyName}/status` suspends
  (reversible) or revokes (terminal). A change that would strand a signing
  transmitter answers `409`.
- Minting answers with a `Key-Id` header. PEM uploads accept EC P-256 and
  ML-DSA-65 certificates.

## Delivery and storage

- **Idempotent ingest** (ADR 0017): `jti` is the dedup key. A re-delivered SET
  is stored once and is not routed again.
- **One `deliveries` collection** replaces `pendingEvents` and
  `deliveredEvents`: one document per `(sid, jti)`.
- **Durability contract** (ADR 0038): every acknowledged SET is
  majority-journaled. When the store cannot accept a SET, push and SSTP ingest
  answer `503` with `Retry-After` (was `400`).
- **Throughput.** Batched ingest, parallel verification, pooled connections,
  group commit, concurrent push per stream (`I2SIG_PUSH_CONCURRENCY`), several
  outstanding polls and SSTP batches, and poll responses signed by a worker
  pool. On the dev bed push went from about 38 to over 500 events/s; a
  two-node cluster drained poll at over 2,000 events/s. Numbers and method are
  in `docs/perf/`.
- **Opt-in local write-ahead log** (`I2SIG_STORE_WAL=local`, ADR 0045) with a
  per-stream `durability` attribute. A multi-node deployment refuses to start
  with it.
- **Wire-shaped persistence** (ADR 0030): `events` and `subject_filters` are
  stored as they appear on the wire. Old rows are read in place. A payload
  member starting with `$` is rejected.
- **Retention.**
    - A stream may set a retention window; a delivery reference is reaped
      after it, and a body is purged once nothing references it. With no
      window, events are kept forever, as before.
    - Delivered ping (verification) events are purged after
      `I2SIG_PING_RETENTION` (default `24h`, `0` to keep) (ADR 0048). v0.11
      kept them forever.
- **Poll.** A response is compact JSON. `maxEvents: 0` is acknowledgement
  only. A rejected JTI is reported in `setErrs` and acked.
- **Push.** A receiver's `invalid_request` no longer disables the stream by
  itself; the server checks the SET with its own validators first.
- **MongoDB 8.0** is the target. Ingest uses the 8.0 multi-collection
  `bulkWrite` and falls back on older servers.

## Cluster

- Poll transmitters and SSTP acceptors take a cluster lease. Every node still
  answers `POST /poll/{id}` and `POST /sstp/{id}`; a non-owner forwards to the
  owner over `POST /_cluster/claim`.
- A lease takeover can send a SET twice but cannot lose one; the receiver
  drops the duplicate by JTI. `I2SIG_LEASE_SAFETY_MARGIN` (default `5s`) sets
  how early an owner stops acting before its lease ends.
- Nodes advertise themselves with `I2SIG_CLUSTER_ADVERTISE_URL`. Stream changes
  reach other nodes at once instead of at the 40 s sync, and stale node and
  lease rows are reaped.
- A pause or disable stops a live push runner on whichever node holds it, and
  a takeover never overwrites a status an operator set.

## Event validation

Off by default (ADR 0029). Per receiver stream `event_validation`, or
`I2SIG_STREAM_EVENT_VALIDATION`, takes `NONE`, `WARN`, `ENFORCE` or `STRICT`.
Validators cover CAEP (5 event types), RISC (9), SCIM / RFC 9967 (12) and four
experimental WISE types. `I2SIG_EVENT_TYPES_EXTRA` adds event URIs to the
supported catalog (ADR 0032). The library is `pkg/goSetValidate`.

## Operations

- **Metrics.** Queue-time and ack-time histograms, per-stream backlog depth and
  oldest age, event-age-at-receipt, peer-claim counters, a validation counter
  and a JWKS-readiness gauge. See `docs/Metrics.md`.
- **Image.** The image carries a `HEALTHCHECK` against the default TLS
  listener; override it when TLS is off or the port differs.
- **Build.** `build.sh` and `Dockerfile.multistage` are removed. Make is the
  only entry: `make build-docker` builds a local image, `make build-publish`
  validates a multi-arch build, and `make qa` is the full local gate. The
  `goSignals` CLI is built into `bin/`.
- **Profiling.** `I2SIG_PPROF_ADDR` opens an opt-in pprof listener.
- **Compose stacks.** Keycloak 26.7.3 with `KC_*` variable names, PostgreSQL
  18 (volume at `/var/lib/postgresql`), MongoDB 8.0.13, dev admin on host port
  8081.
- **Demo stacks run the published image.** `docker-compose.yml`,
  `docker-compose-cluster.yml` and `docker-compose-spiffe.yml` pull
  `independentid/i2gosignals:0.12.0` instead of a locally built image, and
  mount `config/certs` read-only into each server. `make run` and
  `make run-spiffe-demo` no longer build; they only generate the certificates
  when missing. The `-dev` files still build from source.
- **Logging.** A retried store failure logs at WARN, not ERROR.

Every variable named here is described in `docs/configuration_properties.md`.

## Toolchain and dependencies

- Go `1.26.4` → `1.27.4`. The code uses 1.27 standard-library packages
  (`uuid`, `crypto/mldsa`, `encoding/json/v2`), so an older toolchain cannot
  build it. 1.27.4 fixes GO-2026-6859 (`net/http`).
- Every module is at its latest stable release, including major versions:
  keyfunc v3.9.2, jwkset v0.12.0, golang-jwt v5.3.1, go-jose v4.1.9,
  mongo-driver v2.10.1, go-spiffe v2.9.0, grpc v1.85.0, x/crypto v0.59.0,
  x/net v0.63.0.
- The Chainguard `bash` runtime base is re-pinned to its current digest.

## Upgrade

Take a backup first. **There is no path back:** once v0.12.0 has started on a
store, an older server must not be run against it.

Before the first start:

1. **Check for duplicate JTIs.** The events collection gets a sparse-unique
   index on `jti`. If duplicates exist the server logs a WARN, the index is not
   built and duplicate suppression is off until you remove them and restart.
   Group the collection by `jti` to find them.
2. **Build the ping-purge indexes in a maintenance window** if the store is
   large: `{ping:1, state:1, createdAt:1}` on `deliveries` (partial,
   `ping: true`) and `{receivedAt:1}` on `events` (partial, verification event
   types). Otherwise they are built at first start. See
   `docs/operations.md`, "Ping events are purged after 24 hours".
3. **Check every outbound endpoint is `https`**, or set `tx_allow_plaintext`
   on the stream.
4. **Check every receiver stream has a trust anchor** (bearer, mTLS, or issuer
   with JWKS URL). A stream without one is disabled at startup.
5. **Decide the key algorithm.** Set `I2SIG_KEY_ALG=RS256` to keep minting RSA
   keys, and pin `signing_alg` on streams whose receivers accept only RS256.
   An issuer that holds only its existing RSA key keeps signing with it.
6. **In a cluster,** set `I2SIG_CLUSTER_ADVERTISE_URL` per node, and set
   `I2SIG_POLL_DEFAULT_TIMEOUT` / `I2SIG_POLL_MAX_TIMEOUT` to the same values
   on every node.

At first start:

- `pendingEvents` and `deliveredEvents` are copied into `deliveries` and
  dropped. Stream starts wait until it finishes.
- Pre-upgrade ping deliveries are marked, then the purge works through the
  backlog oldest-first over several runs. Disk space is not returned; run
  `compact` yourself, one member at a time.
- Key selection is by creation time. The first rotation after the upgrade
  takes effect at once. See `docs/operations.md`, "Signing key selection".

Afterwards, update clients that relied on: `200` on stream delete; credentials
readable on GET; the three OAuth fields in the SSF configuration document; the
hard-delete key route; `400` from ingest on a store failure; the mixed-case
SCIM `asyncResp` URI; or a ksuid-shaped `jti`. A new `jti` is a 36-character
UUIDv7, which is still time-ordered; existing events keep the `jti` they have.

If you build from source, your `go` must be ≥ 1.27.4 (or allow Go's automatic
toolchain download).

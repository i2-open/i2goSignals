# goSignals v0.12.0-alpha.22

Released: TBD

Compare: [v0.12.0-alpha.21...v0.12.0-alpha.22](https://github.com/i2-open/i2goSignals/compare/v0.12.0-alpha.21...v0.12.0-alpha.22)

## Why this release

A retention release. Spec planning#142 (#388, #389, ADR 0048) purges
delivered ping events, SSF Verification Events sent or received, 24 hours
after this server stored them. Until now a community server kept every ping
forever beside its data events.

This alpha has **behaviour changes operators must act on**:

- **Delivered pings are deleted after `I2SIG_PING_RETENTION` (default
  `24h`).** One node per cluster runs the purge every 6 hours under the
  `maintenance:ping-purge` lease. A ping still pending on any stream is never
  purged; data events are not touched. `I2SIG_PING_RETENTION=0` turns it off.
- **The first run drains the whole stored backlog.** It works oldest-first in
  one-hour windows of stored time with a one-second pause between windows,
  over as many runs as it takes, so a server with months of pings spends its
  first runs on them. Pings stored before this release are dated by their
  insertion time (MongoDB ObjectId `_id`).
- **Two indexes are built at the first start.** `{ping:1, state:1,
  createdAt:1}` partial on `ping: true` on `deliveries`, and `{receivedAt:1}`
  partial on Verification Event types on `events`. On a large store, build
  them beforehand in a maintenance window to keep the build off the upgrade.
- **A one-shot backfill marks pre-upgrade ping deliveries** at startup, after
  the deliveries migration, on one node (lease `migration:ping-marker`). It
  records a done flag in the `migrations` collection; a failure logs a `WARN`,
  does not stop the server and is retried at the next start.
- **Disk space is not returned.** The purge never runs `compact`; run it
  yourself on `events` and `deliveries`, one member at a time, if you want the
  space back after the first drain.

See [`operations.md`](../operations.md#ping-events-are-purged-after-24-hours).

## Ping purge (spec planning#142, #388, #389, ADR 0048)

- **Stored-at clock and ping marker** (#388). Every body write stamps
  `receivedAt`; every delivery write path marks a ping's delivery record
  (`ping: true`). The purge deletes delivered ping records, then the ping
  bodies stored in the window that no pending record references.
- **Runner** (#388). `services.PingPurger`, oldest-first one-hour windowed
  deletes, the last purge time on the lease row, one `INFO` summary per run,
  no metrics.
- **Pre-upgrade data** (#389). Bodies without `receivedAt` fall back to the
  ObjectId `_id` time (memory: the sort time); the fallback query is index
  backed. The `migration:ping-marker` backfill marks legacy delivery records
  in batches of 1000; the memory store derives the marker when it loads its
  files. A backlog test drains 30 days of pre-upgrade pings across cancelled
  and resumed runs.

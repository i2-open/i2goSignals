# Architecture Decision Records

This directory is the canonical home for i2goSignals design decisions. Each ADR
records one non-trivial decision — its context, what was decided, and the
consequences — so the rationale survives and the same fix or regression is not
re-attempted. (It replaces the old append-only `DECISIONS_LOG.md`; routine bug
fixes now live in git history, not here.)

## When to write an ADR

Write one for non-trivial architecture, or a dependency or definition
requirement that should be remembered. A routine bug fix does not need an ADR —
git history is enough.

## Convention

- **Filename:** `NNNN-kebab-case-title.md`, where `NNNN` is the next sequential
  number.
- **Header:** the shared brand hero `<picture>` block (see any existing ADR).
- **Body:** `# N. Title`, then `Date:`, then `## Status` (Accepted / Superseded /
  …), `## Context`, `## Decision`, `## Consequences` (Positive / Negative), and
  `## Related` (links to sibling ADRs, issues, and the operator-facing docs).
- A decision that revises an earlier one either supersedes it (mark the old one
  `Superseded by NNNN`) or is folded in as a dated `## Update` section when it is
  a refinement rather than a reversal.

All ADRs below are **Accepted** unless noted.

| [0031](0031-sstp-inbound-route-mode.md) | SSTP inbound honours its direction's `RouteMode` | `HandleEvent`'s unconditional `if sstpInbound { return nil }` guard treated every SSTP-ingested SET as `IMPORT`, silently dropping hop 2 of `A --sstp--> goSignals --sstp--> B`. The guard now reads the inbound direction's `RouteMode`: `IMPORT` stays terminal, `FORWARD`/`PUBLISH` fan out as an RFC 8935 push receiver does. The forward-vs-re-sign choice stays at delivery time on the **outbound** stream, so the two routing modes are indistinguishable on the inbound leg — a deliberate, recorded deviation from the issue's AC. `IsReceiver()` cannot carry the check (SSTP is `ReceiveSstp`). `sstpInboundRouteMode` normalises both a blank `RouteMode` and a nil `SstpInbound` to `IMPORT` so legacy records don't start fanning out and a pair with no inbound half can't route on its **tx** mode. `routeEventToSstpPairsLocked` takes an `excludeTxSid` (tx SID, not `PairId` — it keys both fan-out maps and survives an unpopulated `PairId`) so a SET is never echoed back out the pair it arrived on. |

| [0033](0033-jwks-url-presence-discriminates-expected-verification-material.md) | Expected verification material is discriminated by issuer-JWKS-URL presence | A receive direction expects a JWKS iff `IssuerJWKSUrl` is configured (`"NONE"` normalises to absent) — not `SigningOnly`, not "a key was found". With a URL, a transient fetch failure or a zero-key body is *unresolved* and lazily retried (10s → ×2, capped at 5m to match `RefreshRateLimit`); without one, the internal lookup is authoritative and never retried, sound only because ADR-0066 §D2 requires a trust root for L2=None. | [0034](0034-ml-dsa-set-signing.md) | ML-DSA-65 SET signing is a per-stream opt-in over a dual-key JWKS | RFC 9964 / FIPS 204 post-quantum SET signatures selected per stream by `StreamConfiguration.signing_alg` (`""`/`RS256` default, `ML-DSA-65` opt-in; `omitzero`, so an existing stream is byte-identical on the wire). An issuer holding any ML-DSA stream publishes **both** keys in its JWKS under distinct `kid`s, so a receiver that has never heard of `kty:"AKP"` skips it and keeps verifying its RS256 stream unchanged; the key store's records gained an `Alg` discriminator whose empty value means RSA. `golang-jwt`/`keyfunc`/`jwkset` have no ML-DSA support (golang-jwt#508/#519 open), so `pkg/goSet/mldsa` supplies the signing method and AKP JWK codec through those libraries' own extension points (`jwt.RegisterSigningMethod`, `keyfunc.NewGivenCustom`) and is shaped to be deleted when upstream ships. `AllowedAlgs()` widens to `{RS256, ES256, ML-DSA-65}` on every node — the allow-list gates the header before key lookup, and a receiver must verify a PQ SET whether or not it signs one. Cost is bytes, not CPU: ~3.3 KB more per SET, which is the whole reason the opt-in is per-stream. `cmd/genTlsKeys` gains an independent, off-by-default `CERT_KEY_ALG=ML-DSA-65` for internal mTLS. |
